# GeneaSphere（寻根路）菜单 / 路由全量验证测试报告

- **测试日期**：2026-08-16
- **被测范围**：家族管理后台 `/zupu/:slug/*`、族员用户中心 `/user-center/*`、平台管理后台 `/platform-admin/*`
- **验证方式**：
  1. **静态交叉核对**（本地代码）：脚本 `scripts/audit-menus-routes.mjs` 将三个布局的 67 个菜单项与 `apps/web/src/router/index.ts` 路由表逐一比对；
  2. **浏览器实测**（远程部署 `http://43.134.232.175`，与本地同一代码库；本机沙箱无法建立数据库隧道/运行本地后端，故以远程后端+本地代码审计组合验证）：Playwright(Edge headless) 逐项点击 3 个后台的全部菜单，检查 URL 落点、404、空白页、错误 toast、控制台异常、菜单高亮；可疑项再直连 URL 复验；
  3. **截图存档**：`temp/e2e-shots/`（55+ 张）、报告数据 `temp/e2e-report.json`、`temp/verify2-report.json`。

| 项 | 家族后台 | 用户中心 | 平台后台 |

## 三、实测发现的问题（按严重度）

### P0 功能损坏（页面可打开，数据加载必然失败）

| # | 位置 | 现象 | 根因（本地代码） |
|---|---|---|---|
| BUG-01 | 家庭关系变更审核 `/zupu/:slug/family-relation/reviews` | 控制台 `ReferenceError: clanId is not defined`，列表永远为空 | `FamilyRelationReviewsPage.vue` L144-146：从 `location.search` 读 `clanId` 却引用未定义变量 `clanId`（应为路由参数 `slug`），请求直接抛异常 |
| BUG-02 | 子女归属争议 `/zupu/:slug/family-relation/disputes` | 报错 `clanSlug is required`，列表为空 | `FamilyRelationDisputesPage.vue` L54-55：同款错误模式（query 读 `clanId` 兜底 `'1'`），API 未收到合法 slug |
| BUG-03 | 信息修改审核 `/zupu/:slug/invite/reviews` | 请求 403，列表为空 | `ModificationReviewPage.vue` L57/L76：`clanId = route.query.clanId \|\| '1'`，且向后端传参名是 `clan_id`，而后端 `@Query('clan_slug')` 只认 `clan_slug` → 参数名不匹配被拒 |
| BUG-04 | 用户中心·我的工具箱 `/user-center/toolbox` | `/api/toolbox/credits`、`/api/toolbox/packages`、`/api/toolbox/history` 三个请求全部 404，页面退化为"AI 工具暂不可用" | 后端 `apps/server/src/toolbox/toolbox.controller.ts` 前缀为 `@Controller('toolbox')`，而全项目其他控制器均为 `@Controller('api/xxx')` → 前端调 `/api/toolbox/*` 404。**注意**：前端显示"该功能尚未启用"是能力开关的兜底文案，实际是接口 404，容易被误判为"功能未开通" |

> 说明：BUG-01~03 是同一历史遗留问题的三种表现——页面从旧 `/admin/*?clanId=xx` 时代迁移到 `/zupu/:slug` 后，读取家族 ID 的方式未同步更新（仍在 query 中读 `clanId`，且 01/03 还引用了未定义变量/错误参数名）。建议统一用 `useRoute().params.slug` 并核对后端参数名。

## 四、菜单优化方案

### 方案 A（推荐，改动小收益大）：合并"单例分组"，16 组 → 8 组

家族后台现状 16 组 39 项，其中 7 个分组 ≤2 项。建议按"职责域"重组为 8 组：

| 新分组 | 收录现有项 |
|---|---|
| **概况** | 控制面板、族谱树、册谱、数据统计 |
| **人员与权限** | 成员列表、权限分配、邀请二维码、验证记录、信息修改审核、PDF 导入管理 |
| **审核中心** | 影像审核、生平审核、家庭关系变更审核、子女归属争议、举报管理 |
| **内容与影像** | 影像库、相册管理、家庭图册（从"工具记录"移入）、公告管理、题库管理、大事件列表、迁徙管理 |
| **寻亲与合并** | 认亲申请、寻亲帖管理 |
| **族谱与印刷** | 生成族谱、历史版本、订单管理、迁徙历史视频、大事件视频 |
| **通知与短信** | 发送短信、余额管理 |
| **系统设置** | 隐私配置、字辈管理、家族信息、云存储、数据导出、AI工具使用记录、回收站、操作日志 |

- 收益：顶级项从 16 → 8，滚动减半；单例组消失；同类功能相邻。
- 附带修复：UX-07（家庭图册归类）、UX-12（统计并入概况）。
- 用户中心同样把 4 组重排为：**个人管理**(个人资料/我的家族/家庭关系/我的验证/验证记录)、**内容与空间**(我的时光/家庭图册/我的标注/我的记忆贡献/我的音像墙/个人空间)、**互动与工具**(我的工具箱/我的小组/寻找小伙伴/直系血缘视频)、**交易**(我的订单)，解决 UX-11。

### 方案 B（增强，长期）：菜单配置化 + 权限裁剪 + 搜索

1. 把三个布局的菜单抽成 `src/config/menus.ts` 数据驱动，路径/图标/权限一次定义、路由与菜单同源，杜绝"菜单改了路由没改"；
2. 菜单按角色/能力裁剪：如「短信通知」在未配置短信能力时整组隐藏（现在点进去才提示未启用）；「AI工具使用记录」同理；
3. 侧边栏顶部加**菜单搜索框**（输入即过滤子项），彻底解决项多难找；
4. 移动端：家族后台/平台后台补齐抽屉式侧边栏（用户中心已有）；用户中心修复通知铃铛。

### 优先修复清单（建议顺序）

1. BUG-01~03：三个审核页统一改为 `useRoute().params.slug`，核对后端参数名（`clan_slug`）；
2. BUG-04：`ToolboxController` 前缀补 `api/`（或前端去掉 `/api`，但全项目风格是控制器带前缀，推荐改控制器）；
3. UX-01：平台后台菜单图标改用与家族后台相同的 `iconMap` 引用组件方式；
4. UX-02：`request.ts` 401 处理加"当前页面为平台/家族后台时优先刷新 token 重试一次，仍失败才登出"；
5. UX-03/04/08/09：用户中心铃铛事件、子页菜单前缀高亮、个人设置文案/目标、分组展开策略（允许多组展开）。
