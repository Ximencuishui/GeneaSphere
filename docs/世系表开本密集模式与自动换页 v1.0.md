## 1. 背景：PR#1 实施后发现的真实业务痛点

> 用户原话：「用演示数据朱熹家族谱 demo 数据 PDF 作为视觉对照」

PR#1 在 demo 数据上验证时发现：

| 痛点 | 量化 | 影响 |
| --- | --- | --- |
| **繁衍高峰代内容溢出标题栏** | 第 16 世 76 人 / 第 17 世 76 人 / 第 18 世 72 人；标准密度单页只能容纳 ~16 人/代 | 实际族谱（百年家族 30+ 代）必触发，不可送印 |

| 繁衍高峰代可读性 | 内容溢出标题栏 | 前半 + 后半两列，强制 condense-strong | 可送印 |
| 维护成本 | 三份实现需同步 | 一处真理（`scripts/shixi-render.cjs`） | 单点修改 |

## 2. 设计目标

1. **自适应密度**：单代人数决定字号、行高、间距，无需人工干预
2. **自动分页**：单代人数 > 16 时，拆为左右双列 split-page（单页容量翻倍到 32）
3. **一处真理**：后端 PDF / 前端预览 / 离线脚本 三处同构，避免漂移
4. **不破坏 PR#1**：与《册谱数据模型决策清单》§F3 config 字段完全兼容，新增 `.condense` / `.condense-strong` / `.shixi-grid-split` CSS 类名仅扩展语义

## 3. 设计方案

### 3.1 三级密度模式

| 模式 | 触发条件（单代人数） | 姓名字号 | 行字号 | 行高 | 上下间距 | 适用场景 |
| --- | --- | --- | --- | --- | --- | --- |
| `normal` | ≤ 6 人/代 | 13pt | 8.5pt | 1.7 / 1.6 | 3mm | 标准族谱、繁衍初期 |
| `condense` | 7 ~ 12 人/代 | 11pt | 8pt | 1.5 | 2mm | 中等密集、过渡期 |
| `condense-strong` | > 12 人/代 | 10pt | 7.5pt | 1.3 | 1.5mm | 繁衍高峰代 |

#### CSS 实现（与 cepu.service.ts 的 `shixiTableCss()` 一致）

```css
/* 中等密集：7-12 人/代 */
.shixi-page.condense .shixi-person { margin: 2mm 0; line-height: 1.5; }
.shixi-page.condense .shixi-name { font-size: 11pt; margin-bottom: 2px; }
.shixi-page.condense .shixi-line,
.shixi-page.condense .shixi-bio { font-size: 8pt; line-height: 1.5; }

/* 强密集：> 12 人/代（单代多列时强制启用） */
.shixi-page.condense-strong .shixi-person { margin: 1.5mm 0; line-height: 1.3; }
.shixi-page.condense-strong .shixi-name { font-size: 10pt; margin-bottom: 1px; }
.shixi-page.condense-strong .shixi-line,
.shixi-page.condense-strong .shixi-bio { font-size: 7.5pt; line-height: 1.3; }

/* 不显示连接线（兼容原有 config.show_generation_connector=false） */
.shixi-page.no-connector .shixi-col::before,
.shixi-page.no-connector .shixi-col::after { display: none; }
```

### 3.2 自动密度选择算法

```typescript
function pickShixiDensity(
  chunkGens: number[],
  byGen: Map<number, ShiluEntry[]>,
): 'normal' | 'condense' | 'condense-strong' {
  let maxPerGen = 0;
  for (const g of chunkGens) {
    const list = byGen.get(g) || [];
    if (list.length > maxPerGen) maxPerGen = list.length;
  }
  if (maxPerGen > 12) return 'condense-strong';
  if (maxPerGen > 6) return 'condense';
  return 'normal';
}
```

**算法要点**：
- 按 **chunk 内单代人数的最大值** 选择密度（而非总人数）—— 保证每列内容都放得下
- 阈值 6 / 12 与 CSS 量化表严格一致——保证 PDF / 前端 / 离线脚本三处同步

### 3.3 单代左右双列（split-page）

**触发条件**：当前 chunk 内**任一**单代人数 > `HARD_LIMIT`（= 16）

**实现策略**：
- 该代拆为左右两列，**前半 + 后半**，共 1 页（单页容量翻倍到 32）
- 列头分别标注：`第 N 世·前半` / `第 N 世·后半`
- 页面标题：`族谱第 N 世世系表(N 人)`（N 为该代总人数，让翻页者一眼知密度）
- **强制启用 `condense-strong`**（高密度是 split-page 的前置条件）
- chunk 中其它代（≤ 16 人）继续走标准密度页

#### HTML 模板（与 cepu.service.ts 一致）

```html
<section class="shixi-page condense-strong">
  <div class="shixi-page-dot"></div>
  <div class="shixi-title">族谱第16世世系表(76人)</div>
  <div class="shixi-grid">
    <div class="shixi-col">
      <div class="shixi-col-header">第16世·前半</div>
      <!-- 排序后的前 38 人 -->
    </div>
    <div class="shixi-col">
      <div class="shixi-col-header">第16世·后半</div>
      <!-- 排序后的后 38 人 -->
    </div>
  </div>
</section>
```

### 3.4 三处真理同构

> 这是本文档**最重要的约束**：后端 PDF / 前端预览 / 离线脚本 三处必须**逐字符同构**，任一处修改必须同步另外两处。

| 实现 | 文件 | 关键函数 |
| --- | --- | --- |
| **后端 PDF 渲染** | `apps/server/src/cepu/cepu.service.ts` | `renderShixiTablePage(gens, ..., density)` / `renderShixiSplitColPage(gen, entries, cfg)` / `pickShixiDensity(chunkGens, byGen)` / `buildShixiTablePages(entries, cfg, ...)` |
| **前端在线预览** | `apps/web/src/views/CepuPage.vue` | `shixiTablePages` computed + `pickShixiDensity` + 模板 `v-if="isSplitCol"` 分支 |
| **离线 puppeteer 脚本** | `scripts/shixi-render.cjs` | `renderPage(gens, byGen, title, { density })` / `renderSplitColPage(gen, people, opts)` / `pickDensity(chunkGens, byGen)` / `buildShixiTablePages(entries, pageGen, isFemaleOnly)` |

**同步保障**：
- `scripts/shixi-render.cjs` 显式 `module.exports = { buildShixiTablePages, renderPerson, renderPage, renderSplitColPage, esc, pickDensity }`
- `scripts/preview-shixi-demo-full.cjs` 通过 `require('./shixi-render.cjs')` 引用同一份真理
- 后端 `cepu.service.ts` 的算法与 `shixi-render.cjs` 1:1 对应（TypeScript 5 → JavaScript 5 直译）
- 前端 `CepuPage.vue` 的 `pickShixiDensity` 与上述三者阈值（6 / 12 / HARD_LIMIT=16）严格一致

### 3.5 验证数据规模

- **朱熹族谱 demo**（`scripts/demo-data-pure.cjs`）：1000 人 / 24 代
- 世代分布：
  - 第 1-5 世：2 ~ 8 人（normal）

## 5. 兼容性

### 5.1 config 字段

- **无新增字段**：《册谱数据模型决策清单》§F3 的 `config` schema 完全兼容
- 仍使用：`layout: 'shixi_table'` + `page_gen_count`（默认 5）+ `show_generation_connector` + `surname_color`
- 密度由算法自动判断，**不暴露给 admin 配置**（避免误调）

### 5.2 CSS 类名

| 类名 | 来源 | 用途 |
| --- | --- | --- |
| `.shixi-page` | PR#1 已定义 | 单页容器 |
| `.shixi-grid` | PR#1 已定义 | 列布局容器 |
| `.shixi-col` | PR#1 已定义 | 单列容器 |

| `.no-connector` | PR#1 已定义 | 不画顶端连接线 |
| **`.condense`** | **v1.0 新增** | 中等密度（7-12 人/代） |
| **`.condense-strong`** | **v1.0 新增** | 强密度（> 12 人/代） |
| **`.shixi-grid-split`** | **v1.0 新增** | 双列 split-page 布局 |

### 5.3 旧版兼容性

- 一期（PR#1）用户已生成的 PDF 不受影响（CSS 仅追加新规则，未修改旧规则）
- 现有 admin 配置（`page_gen_count: 5`）继续走原分页逻辑，仅在单代人数 > 16 时触发 split-page
- 前端 CepuPage 的 `.shixi-person` 选择器继续工作（PR#1 已有的 hover / focused 动画不受影响）

### 5.4 Word 导出

- Word 导出仍走横排苏式（《册谱模块需求文档（PRD）》§2.5 决定）
- shixi_table 版式的 Word 输出（mso 竖排 + mso-vertical）**留待二期续**
- 当前二期续的 Word 导出仅支持 `layout: 'su'` / `layout: 'ou'`，`layout: 'shixi_table'` 仍以 PDF 为唯一载体

## 6. 后续可做（待用户确认优先级）

1. **Word 导出支持 shixi_table 版式**
   - mso 竖排（`writing-mode: tb-rl` + `mso-vertical`）+ 中文楷体嵌入
   - 输出 `.doc` 兼容 Microsoft Word / WPS / LibreOffice

2. **密度阈值通过 config 暴露**
   - `config.density_thresholds = { condense: 6, condense_strong: 12, hard_limit: 16 }`
   - admin 可针对特定族谱调整（如人口较少的族可提高 condense_strong 阈值）

3. **四密度扩展**
   - 新增 `sparse` 模式（≤ 3 人/代）：放大字号到 16pt，给小家族更舒展的版式
   - 与 condense-strong 共存，由最大人数自动选择

4. **PDF 预览加水印**
   - 内部审校稿：底部"GeneaSphere 内部审校 · 非正式印本"水印
   - 控制卷宗版本自动加注 v{n} + 生成时间戳

5. **世系表横向导出**
   - 当前仅支持纵向（writing-mode: vertical-rl），横向 left-to-right 版式可作为"非中式开本"选项（如现代家谱）
