# 族谱管理员「修谱全流程」用例设计

> 项目：寻根路 · GeneaSphere
> 模块：族谱管理员后台 · 修谱工作流（控制台 / 【修谱】功能顶端）
> 版本：v1.0 · 2026-08-17
> 关联代码：`apps/server/src/genealogy-workflow/` · `apps/web/src/components/admin/GenealogyWorkflowBar.vue`

---

## 1. 业务背景

管理员修谱是一条**长流程**，横跨导入、OCR、校对、通知、审核、生成、印刷等多个功能页。
旧后台各页面相互独立，管理员无法一眼看出"修谱修到哪一步、下一步该做什么"。

**目标**：在管理后台**控制台**与**【修谱】功能顶端**提供一条"修谱工作流"可视化进度条，
展示全流程阶段、当前所处阶段、已完成数量，并可点击阶段直达对应功能页，让管理员**一目了然**。

**全流程**（7 个主阶段，其中"旧谱电子化"含 4 个子阶段）：

```
新建族谱
  └─ 旧谱电子化
       ├─ 导入与拍照（旧电子文档导入 + 拍照）
       ├─ OCR 识别
       ├─ 左右对照编修
       └─ 保存数据表
发通知族员（短信 / 微信 / 站内）
族员自行更改
审核
新谱建成
印刷出谱
```

## 2. 角色与权限

| 角色 | 说明 | 权限 |
|---|---|---|
| 族谱管理员（OWNER） | 家族创建人 / 最高管理者 | 查看工作流、操作全部修谱功能 |
| 编辑者（ADMIN） | 被分配的管理员 | 查看工作流、操作修谱功能 |
| 族员（EDITOR / VIEWER） | 普通族员 | 不可见工作流（403） |
| 匿名用户 | 未登录 | 不可访问（401） |

权限实现：`GET /api/genealogy-workflow/status` 挂 `JwtAuthGuard`，内部经
`AdminService.requireAdmin(clanId, userId)` 校验 OWNER/ADMIN。

## 4. 用例详述

### UC-11 查看修谱工作流进度（核心用例）

- **前置条件**：管理员已登录；家族存在。
- **主流程**：
  1. 管理员进入控制台 `/zupu/:slug` 或【修谱】子页面（历史版本、PDF 导入管理）。
  2. 页面顶部渲染"修谱工作流"条：7 个主阶段节点 + 进度百分比 + 旧谱电子化 4 个子步骤。
  3. 后端按家族真实业务数据推导各阶段状态（done / current / todo）：
     - 绿色 ✓ = 已完成；橙色脉冲 = 当前进行中；灰色 = 未开始。
  4. 点击任意阶段节点 → 跳转对应功能页。
- **备选流程**：
  - 后端不可用 → 显示"加载失败 + 重试"，不阻塞页面其余内容。
  - 家族不存在 → 提示"未找到该家族"。
- **数据规则（阶段推导口径）**：

| 阶段 | 完成条件（该家族下计数 > 0） | 数据来源 | 跳转页 |
|---|---|---|---|
| 1 新建族谱 | 族谱存在（恒完成） | `clans` | 家族信息 |
| 2.1 导入与拍照 | `pdf_import_logs` | 导入记录 | 历史版本 |
| 2.2 OCR 识别 | `pdf_import_logs.parse_mode='ocr'` | 扫描件 OCR 任务 | PDF 导入管理 |
| 2.3 左右对照编修 | `pdf_parse_temp.is_corrected=true` | 校对记录 | PDF 导入管理 |
| 2.4 保存数据表 | `pdf_import_logs.success_records>0` 或 `persons` | 族员数据表 | PDF 导入管理 |
| 3 发通知族员 | `sms_send_records` 或 `notifications(clan)` | 短信 / 站内通知 | 公告通知 |
| 4 族员自行更改 | `person_modification_requests` | 修改申请 | 信息修改审核 |
| 5 审核 | 已审（APPROVED/REJECTED）的修改申请或传记 | 审核记录 | 信息修改审核 |
| 6 新谱建成 | `genealogy_documents` 或 `book_volumes` | 族谱版本 / 册谱卷宗 | 生成族谱 |
| 7 印刷出谱 | `print_orders` | 印刷订单 | 印刷订单 |

- **进度**：10 个粒度步（1 + 4 子阶段 + 5 单步阶段），`progress = 完成粒度步 / 10`。
- **当前阶段**：自上而下第一个未完成阶段；全部完成时显示"全流程已完成"。
- **验收标准**：
  - 任意阶段数据出现后，工作流条在刷新后正确更新（done 数、进度、当前阶段）。
  - 点击阶段跳转 URL 正确。
  - 非管理员访问 → 403；未登录 → 401。

### UC-01 新建族谱

- **主流程**：管理员 `POST /api/clans` 创建族谱（自动生成 slug，创建者为 admin_user_id）。
- **验收**：创建成功后工作流 progress=10%（仅阶段 1 完成），当前阶段=旧谱电子化。

### UC-02 旧谱电子化：导入与拍照

- **主流程**：管理员上传旧谱 PDF（电子文档或拍照件）`POST /api/import/pdf/upload`
  → 后端写入 `pdf_import_logs`（status=pending）→ 异步解析。
- **验收**：导入记录落库；工作流 2.1 变为 done。

### UC-03 旧谱电子化：OCR 识别

- **主流程**：解析时若判定为扫描件（文本过少），自动切换 OCR（Tesseract.js / 腾讯云 OCR），
  识别后提取世系条目；`parse_mode='ocr'` 落库。
- **验收**：扫描件任务记录 `parse_mode='ocr'`；工作流 2.2 变为 done。
  （文字版 PDF 无 OCR 步骤，2.2 视为无需执行，可由管理员手动标记或保持待办。）

### UC-04 旧谱电子化：左右对照编修

- **主流程**：管理员在导入管理页"原文 ↔ 识别结果"左右对照校对，
  `PUT /api/import/pdf/task/:taskId/correct` 提交校对 → 后端写回 `pdf_parse_temp` 并标记 `is_corrected=true`。
- **验收**：校对记录落库；工作流 2.3 变为 done。

### UC-05 旧谱电子化：保存数据表

- **主流程**：管理员确认后 `POST /api/import/pdf/task/:taskId/execute`，
  逐条写入 `persons`（族员数据表），回写 `success_records`。
- **验收**：`success_records>0`（或族员数>0）；工作流 2.4 与 2（旧谱电子化）变为 done。

### UC-06 发通知族员（短信 / 微信 / 站内）

- **主流程**：管理员选择通知渠道：
  - 短信：`POST /api/admin/sms/send`（余额校验 + 能力开关；短信能力未配置时返回 503 CAPABILITY_UNAVAILABLE）。
  - 站内通知：服务端按族下发 Notification（记录 `notifications.clan_id`）。
- **验收**：任一渠道通知记录出现后工作流阶段 3 变为 done。

### UC-07 族员自行更改

- **主流程**：族员核对个人信息，提交修改申请 → 写入 `person_modification_requests`（status=PENDING）。
- **验收**：存在申请后工作流阶段 4 变为 done。

### UC-08 审核

- **主流程**：管理员在"信息修改审核"页逐条审核，
  `PATCH /api/invite/modification-requests/:id`（APPROVED / REJECTED），通过后回写族员信息。
- **验收**：存在已审记录后工作流阶段 5 变为 done。

### UC-09 新谱建成

- **主流程**（两条路径，满足其一即可）：
  - 生成族谱版本：`POST /api/genealogy-documents/:slug`（生成 PDF + 保存历史版本）。
  - 册谱卷宗：`POST /api/cepu/volumes`（录入卷宗正文 / 世录配置）。
- **验收**：存在族谱文档或册谱卷宗后工作流阶段 6 变为 done。

### UC-10 印刷出谱

- **主流程**：族员 / 管理员提交印刷订单（`print_orders`），支付后进入生产与发货流程。
- **验收**：存在印刷订单后工作流阶段 7 变为 done，progress=100%，显示"全流程已完成"。

## 5. 异常与边界用例

| 编号 | 场景 | 预期 |
|---|---|---|
| EX-01 | 未登录访问工作流接口 | 401 |
| EX-02 | 族员（EDITOR）访问工作流接口 | 403 |
| EX-03 | 不存在的家族 | 404（前端提示"未找到该家族"） |
| EX-04 | 后端/数据库不可用 | 前端显示加载失败 + 重试，不影响页面其他内容 |
| EX-05 | 短信能力未配置时发短信 | 503 CAPABILITY_UNAVAILABLE（工作流阶段 3 以站内通知/历史记录兜底） |
| EX-06 | 上传非 PDF 文件 | 400 只允许 .pdf |
| EX-07 | 超大 PDF（>50MB） | 400 文件大小超限 |
| EX-08 | 解析失败（如损坏 PDF） | 导入记录 status=failed + error_message；工作流阶段不推进 |

## 8. 后续扩展（建议）

- 手动推进/回退工作流（管理员在特殊场景下覆盖自动推导，落 `clans.settings_json`）。
- 微信模板消息 / 公众号通知接入后，阶段 3 增加微信渠道计数。
- 阶段级操作引导：当前阶段节点点击后弹出"下一步操作"浮层。
- 印刷订单状态（PENDING→PAID→PRINTING→SHIPPED）细化出谱阶段。
