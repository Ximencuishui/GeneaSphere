# 人物详情需求

文档版本：V1.0  
适用页面：树谱右侧抽屉的「个人详情」（先浏览，再编辑）  
字段来源：GEDCOM 常用标签、华谱人物页、上海图书馆家谱著录里和人物条目相关的项  

树谱卡片仍只显示姓名和生卒年。下面这些字段只出现在详情里。空字段不占一行。

## 1. 页面结构

详情固定五组，顺序不变。某一组里的字段全部为空时，整组不显示。

1. 姓名称谓
2. 生卒籍贯墓葬
3. 家庭关系
4. 个人履历
5. 传记与资料附件

关系里的人名都是链接。点一个人，抽屉换成这个人的详情，并回到只读，不停留在编辑表单。

在世人物的联系方式只对本人和本族管理员可见。已故人物不展示联系方式。

编辑仍走抽屉里的「编辑信息」。这一期详情先把已有数据读全；编辑表单只扩到已经能保存的字段，不在这一期把六组扩展项全部做成输入框。

## 2. 字段

「现有」表示库里已经有列或可以算出来，详情接口还没返回。「没有」表示要加列或加关系类型。

### 2.1 姓名称谓

| 页面字段 | 现有位置 | 这一期 |
|---|---|---|
| 本名 / 谱名 | `persons.full_name` | 显示 |
| 讳 | 没有 | 下一期，单独一列，不和本名混用 |
| 字 | `person_bios.courtesy_name` | 显示。接口要带上 `bio` |
| 号 | 没有 | 下一期 |
| 谥号 | 没有 | 下一期 |
| 乳名、别名、曾用名、绰号 | 没有 | 下一期。四项分开存，详情里合成一行「其他称呼」 |
| 字辈 | `xipai`（按家族 + 世代存一个字） | 显示。用世代去字辈表取字，不在人物上再存一份 |
| 排行 | `family_children.birth_order` | 显示「行 N」。同一人有多条子女记录时，取亲生那条 |
| 世代 | 从始祖沿 `person_ancestry` 的深度 | 显示「第 N 世」。始祖为第 1 世 |

### 2.2 生卒籍贯墓葬

| 页面字段 | 现有位置 | 这一期 |
|---|---|---|
| 性别 | `persons.gender` | 显示 |
| 照片 | `avatar_url`、`thumbnail_url`，老照片在 `media_archives` + `media_person_links` | 头像用已有地址。附件列出关联影像，点开沿用现在的大图预览 |
| 出生日期 | `persons.birth_date` | 显示公历。库里是一个日期时间，有时辰就带上时辰 |
| 农历生日 | 没有 | 下一期，单独文本，不覆盖公历 |
| 出生地 | `persons.birth_place` | 显示 |
| 籍贯 | `person_bios.native_place` | 显示 |
| 逝世日期 | `persons.death_date` | 在世则不显示 |
| 农历忌日 | 没有 | 下一期 |
| 逝世地 | `persons.death_place` | 已故才显示 |
| 享年 | 由生卒年相减 | 两个公历年份都有才显示，不另存 |
| 安葬地点 | `person_bios.burial_place` | 显示 |
| 迁徙 | `migration_events`（迁出地、迁入地、年份、原因） | 按年份列在这一组末尾。`persons.migration_branch` 只作房派名，不代替迁徙记录 |

民族、学历不放在这一组。

### 2.3 家庭关系

人名点击后调用现在的抽屉跳转，聚焦到树上对应卡片。

| 页面字段 | 现有位置 | 这一期 |
|---|---|---|
| 父亲、母亲 | `person_ancestry` 深度 1，用性别区分 | 分两行。父母都缺才写「无记录」 |
| 配偶 | `family_units` | 按 `marriage_order` 排。第 1 任且在婚称原配，之后的在婚称继配，`union_type` 能标出侧室再用侧室。带婚姻起止日期。已结束的写离异或已故 |
| 子女 | `family_children` + 人物 | 按 `birth_order`。关系用现有枚举：亲生、收养、继、过继。早夭读 `person_bios.premature` |
| 兄弟姐妹 | 同一对父母的其他子女 | 详情接口现算，不新造表。排行同样用 `birth_order` |

出继、入赘、兼祧这一期不新造枚举。出继、兼祧先读 `person_bios.adoption_note` 的一段说明。入赘先读婚姻 `union_type`。下一期再把这些收成固定选项。

### 2.4 个人履历

| 页面字段 | 现有位置 | 这一期 |
|---|---|---|
| 功名 / 职务 | `person_bios.achievements` | 整段显示 |
| 民族、学历、职业、毕业院校、工作单位 | 没有 | 下一期，各自一列 |
| 重要事件 | 没有独立表。演示数据里的 `events` 只在前端类型上 | 这一期不编造。下一期用「年份 + 正文」列表，不塞进传记正文 |

### 2.5 传记与资料附件

| 页面字段 | 现有位置 | 这一期 |
|---|---|---|
| 生平小传 | `person_bios.biography` | 显示 |
| 轶事 | `person_bios.anecdotes` | 有则显示在小传下面 |
| 配偶家世 | `person_bios.marital_notes` | 有则显示 |
| 考证说明 | `adoption_note` 只能覆盖出继。来源、失考、存疑没有列 | 这一期只显示已有的出继说明。来源字段下一期 |
| 史料、碑记、证书 | `media_archives`，用 `category` 区分 | 列出已关联的非头像影像。没有分类就归入「资料」 |

联系方式、宗教、血型、墓碑文字、老谱出处、口述人、记录人、录入时间都是下一期。录入时间可先用 `persons.updated_at`，不单开字段。

## 3. 和现在抽屉的差别

现在的只读详情只有：姓名、性别、生卒年、字辈（前端字段，库里没有这一列）、生平（前端 `biography` / `events`）、父母、配偶、子女。

缺的不是页面分组，是接口没把已有表接上：

- `getPersonDetail` 只查了 `persons`，没有 `person_bios`。字、籍贯、葬地、传记、功名都在附表里。
- 出生地、逝世地已经在 `persons` 上，保存接口也能写，详情没显示。
- 子女没有排行和关系类型。父母没有分成父亲、母亲。没有兄弟姐妹。
- 迁徙在 `migration_events`，影像在 `media_person_links`，详情都没查。
- 世代和享年可以算，不必入库。

所以第一期不改表，先把详情读全。第二期再加「没有」的列，并让编辑表单按这五组录入。

## 4. 代码怎么对齐

### 第一期：只改读，不改表

1. `apps/server/src/tree/tree.service.ts` 的 `getPersonDetail`  
   一并查出 `bio`、出生地、逝世地、头像。  
   子女补 `birth_order`、`child_type`，并按排行排序。  
   父母按性别分成父亲、母亲。  
   用父母的子女记录算出兄弟姐妹，排除自己。  
   查这个人的 `migration_events` 和 `media_person_links`。  
   世代：始祖到此人的 `person_ancestry.depth + 1`。字辈：用这个世代查 `xipai`。享年：两个年份都有才返回。

2. `apps/web/src/types/index.ts` 的 `PersonDetail`  
   加上 `bio`、`father`、`mother`、`siblings`、`migrations`、`media`、`generation`、`generation_word`、`age_at_death`。子女类型带上排行和关系。

3. `apps/web/src/components/PersonEditDrawer.vue` 的只读区  
   按五组渲染。空行不渲染。关系点击继续走已有的 `navigate`。  
   编辑态这一期仍只保存现在的姓名、性别、生卒和在世状态。出生地、逝世地接口已经能存，可以放进编辑表单，不必等第二期。

4. 卡片上的 `generation_word`、`biography`、`events` 不再当作详情的数据源。详情以接口为准。树上没有这些字段时，详情仍能从 `person_bios` 读到传记。

### 第二期：补列，再开编辑

在 `person_bios` 增加：讳、号、谥号、乳名、别名、曾用名、绰号、民族、学历、职业、职务、毕业院校、工作单位、农历生日、农历忌日、宗教、血型、墓碑文字、考证与来源说明。

`family_children.child_type` 增加出继。婚姻 `union_type` 固定取值：原配不适用此列、继配看顺序、侧室、入赘。

编辑表单按同一五组做。在世人物的联系方式走已有的用户绑定，不写进人物公开字段。

重要事件用一张 `person_events`（人物、年份、正文、排序），不要再把事迹塞进 `biography` 一段文本。
