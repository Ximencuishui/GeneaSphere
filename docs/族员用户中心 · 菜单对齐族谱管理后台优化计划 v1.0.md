# 族员用户中心 · 菜单对齐族谱管理后台优化计划 v1.0

> 适用版本：GeneaSphere（寻根路）当前主线
> 文档目的：在不动后端接口语义、不破坏多家族 SaaS 与 H5 入口的前提下，把族员用户中心侧栏菜单**对齐族谱管理后台**（AdminLayout）的命名、层级、图标与可达性，同时按"族员角色"裁剪功能权限，给后续 UI 与 PRD 评审提供统一基线。

---

## 1. 背景与目标

### 1.1 现状痛点

族员用户中心（`UserCenterLayout`）的菜单自 2026 年初上线以来，**族员入口**与**族谱管理后台**（`AdminLayout`）长期是"两套独立演进"的菜单体系，导致：

- 命名不一致：管理员侧叫"族员管理 / 影像审核 / 生平审核"，族员侧叫"我的时光 / 我的标注 / 我的记忆贡献"；
- 图标语义分散：管理员"族谱 / 修谱"使用 `Monitor / EditPen`；族员"族谱 / 我的内容 / 互动与工具 / 账户与服务"使用 `Collection / FolderOpened / Tools / User`，视觉家族感弱；
- 层级不一致：管理员"家族概况"是顶级直达项（leaf），族员侧却把"家族概况"塞进"族谱"分组；
- 权限边界模糊：族员页内嵌"家族管理后台"入口，但族员自身没有任何"管理员才能用"的功能映射（例如"我的验证"与管理员的"邀请二维码"是同一资源的两面，却没有相互跳转与差异说明）；
- 重复 / 缺失并存：族员侧"家庭关系"已存在，但管理员侧"家庭关系变更审核 / 子女归属争议"在族员侧完全无对应入口；管理员侧"旧谱 / 修谱 / 印刷"在族员侧无法触达。

### 1.2 目标

| 维度 | 目标 |
| --- | --- |
| 命名 | 同一资源两侧统一标题，例如"我的验证" ↔ "邀请二维码"统一为"我的验证"，管理员侧菜单名保留业务惯用名（"邀请二维码"），但族员侧不再出现"我的验证"+"验证记录"两个易混项 |
| 层级 | 复用 AdminLayout 的"顶级直达 + 顶级分组"二态模型；族员版把"家族概况"提升为顶级直达 |
| 图标 | 复用 iconMap，必要时抽公共 `iconMap.ts` |
| 权限 | 严格遵循"族员 ≠ 管理员"，族员中心**不出现**管理员专属操作入口；管理员专属入口通过底部"家族管理后台"按钮集中跳转 |
| 入口 | 路由层把"族员可访问的子集"显式标注，路由守卫按"requiresAuth + requiresMember"双校验 |

### 1.3 不在本计划范围内

- 后端接口增删（除为菜单裁剪新增的"我的待办/我的申请"轻量聚合接口，见 §6.3）
- 移动端 H5（`/h5/*`）改造
- 平台管理员（`/platform-admin/*`）菜单
- 修谱工作流 `GenealogyWorkflowBar` 业务逻辑

## 3. 对齐原则

| # | 原则 | 说明 |
| --- | --- | --- |
| P1 | **同一资源统一入口名** | 管理员"邀请二维码 / 验证记录"在族员侧统称"我的验证"；管理员"族员管理 / 族员信息审核"在族员侧不出现（族员无权自审） |
| P2 | **功能裁剪而非降级复制** | 管理员专属页面（影像审核、生平审核、字辈管理、定谱）不在族员侧"做低权限版"——直接不出现 |
| P3 | **复用而非再造** | 同一组件（如 CepuPage / TreePage）两侧共用，仅入口差异 |
| P4 | **角色可感知** | 族员侧顶栏对当前家族显示角色 tag（已实现），但菜单需要"角色相关项"显式标记（如"我的验证"只在自己所属家族才显示） |
| P5 | **管理员入口收敛** | 族员侧不出现 7+ 条"进入管理后台"类入口，仅保留侧栏底部 1 个"家族管理后台"按钮 |
| P6 | **空态前置** | 未加入任何家族时（`primary_clan` 为空），族员菜单自动隐藏"族谱 / 我的内容 / 互动与工具"中需要家族上下文的项，仅保留"浏览家族 / 个人资料 / 设置 / 我的验证" |

## 4. 目标菜单结构（族员用户中心 v1.0）

### 4.1 顶级直达

| 标题 | 路径 | 角色要求 | 说明 |
| --- | --- | --- | --- |
| 家族概况 | `/user-center/clan-overview` | 已登录 + 已加入家族 | 复用 FamilyOverviewPage 的"族员只读"视图（不显示理事会/修谱小组编辑入口） |
| 首页 | `/user-center` | 已登录 | 原首页卡片保留，作为回退 |

### 4.2 顶级分组

| 分组 | 子项 | 对应管理员侧菜单 | 权限说明 |
| --- | --- | --- | --- |
| **族谱** | 树谱 `/tree/{slug}` | 族谱 → 树谱 | 仅查看 |
| | 册谱 `/cepu/{slug}` | 族谱 → 册谱 | 仅查看（复用 CepuPage，无编辑） |
| | 旧谱 `/zupu/{slug}/genealogy/old` | 族谱 → 旧谱 | 仅查看；管理员入口对族员降级为只读 |

| | 家庭图册 `/user-center/family-book` | 历史影像 → 家庭图册 | 上传 / 查看家庭图册（管理员侧共享相册族员侧仅可见自己与公开部分） |
| | 我的音像墙 `/user-center/videos` | 历史影像 → 相册管理（个人视角） | 个人视频创作 |
| | 我的标注 `/user-center/annotations` | （族员专属） | 族员对族谱节点的批注（管理员在"族谱数据"侧聚合查看） |

| | 个人空间 `/user-center/personal-space/albums` | （族员专属） | 私有相册与留言板 |

| | 我的小组 `/user-center/groups` | （族员专属） | 兴趣小组 |

| | 直系血缘视频 `/user-center/lineage-video` | （族员专属） | AI 血缘短视频 |
| **家族事务**（新增分组） | 我的验证 `/user-center/verify` | 家族管理 → 邀请二维码 | 族员侧的"邀请/被验证"全部聚合到此 |
| | 我的申请 `/user-center/my-applications` | 家族管理 → 族员信息审核 / 寻亲与合并 | 族员提交的所有"申请类"流程（修改族谱信息、寻亲申请、生平补充）聚合查看与撤销 |
| | 家庭关系 `/user-center/family-relation` | 家族管理 → 家庭关系变更审核（族员提交视角） | 族员侧提交入口；管理员审核在 `/zupu/{slug}/family-relation/reviews` |
| | 家族公告 `/user-center/announcements` | 家族管理 → 公告管理（族员只读） | 族员查看家族公告 + 点赞 |
| | 我的订单 `/user-center/orders` | 修谱 → 印刷 | 族员个人印刷订单 |
| **账户与服务** | 个人资料 `/user-center/profile` | （族员专属） | 头像、昵称、邮箱 |
| | 设置 `/user-center/settings` | 设置 → 隐私配置（族员侧精简版） | 隐私偏好、消息推送、注销 |
| | 退出登录 | — | 顶栏已有，菜单中不重复 |

> 注：**家族事务** 是为对齐管理员侧"家族管理"分组而新增的顶级分组，集中所有"族员可执行 / 可查看的家族级事务"。

### 4.3 菜单裁剪规则

| 角色 | 可见分组 | 备注 |
| --- | --- | --- |
| 已登录 + 未加入任何家族 | 族谱（仅"我的家族 / 浏览家族"）/ 我的内容（仅"个人空间"）/ 互动与工具 / 账户与服务 | 其余隐藏，给出"加入家族"引导卡 |
| 已登录 + VIEWER / EDITOR | 全部分组 | EDITOR 不可见"我的申请 / 我的验证"（无修改权） |
| 已登录 + OWNER / ADMIN | 全部分组 + 侧栏底部"家族管理后台"按钮 | 管理员入口仅出现一次 |

## 5. 改动方案（按子系统）

### 5.1 菜单结构改造

**核心文件**：`apps/web/src/layouts/UserCenterLayout.vue`

1. 把 `menuGroups` 重构为 `MenuEntry[]`（leaf + group 二态，参照 AdminLayout），统一类型。
2. 抽公共 `apps/web/src/layouts/menuTypes.ts`，导出 `MenuLeaf / MenuGroup / MenuEntry / iconMap`，两侧复用。
3. 抽出 `getUserCenterMenuGroups(userStore)` 纯函数，便于单测（避免依赖 Vue 上下文）。
4. 实现 `filterMenuByRole(groups, role)`，按 §4.3 裁剪。
5. 把"首页 / 家族概况"作为顶级直达项（leaf），从"族谱"分组上移。

**改造样例（伪代码）**：

```ts
const groups = computed<MenuEntry[]>(() => {
  const clan = userStore.profile?.primary_clan
  const key = clan ? clan.slug || clan.id : ''
  const base: MenuEntry[] = [
    { title: '首页', icon: 'HomeFilled', path: '/user-center' },
    { title: '家族概况', icon: 'DataLine', path: '/user-center/clan-overview' },
  ]
  const grouped: MenuEntry[] = [
    { title: '族谱', icon: 'Monitor', children: [
      { title: '树谱', path: `/tree/${key}` },
      { title: '册谱', path: `/cepu/${key}` },
      { title: '旧谱', path: `/zupu/${key}/genealogy/old` },
      { title: '我的家族', path: '/user-center/families' },
    ]},
    /* ... 其余分组 */
  ]
  return [...base, ...grouped]
})
```

| 公告 | `/api/clans/{slug}/announcements?audience=member`（已存在则复用，不存在补 §6.3） |

### 6.2 已具备的族员提交入口

- 寻亲申请：`POST /api/merge/applications`（族员端 `/h5/genealogy-edit` 已间接调用）
- 生平补充：`POST /api/member-bio/submit`（管理员侧在"生平审核"页面汇总）
- 族员信息修改：`POST /api/member/profile-update-request`

### 6.3 新增聚合接口（轻量）

| 接口 | 用途 | 优先级 |
| --- | --- | --- |
| `GET /api/user/applications?type=bio\|merge\|member&status=pending\|approved\|rejected&page&pageSize` | 我的申请 tab 数据源 | P0 |
| `GET /api/user/notifications/center` | 用户中心统一通知（合并 `unread_count`、审核进度、待办） | P0 |
| `GET /api/clans/{slug}/announcements?audience=member` | 家族公告族员只读列表 | P1（如已存在则跳过） |
| `GET /api/user/badge-counts` | 用户中心红点徽章聚合（`{my_applications, my_verify, family_relation, announcements}`） | P0 |

实现要求：
- 后端模块：`apps/server/src/user-center/`（新增模块），路由前缀 `/api/user`。
- DTO 校验：`class-validator`，禁止裸 `any`。
- 复用 `JwtAuthGuard` + `@CurrentUser()` 装饰器；族员专属端点额外加 `RoleGuard(['MEMBER','EDITOR','VIEWER','OWNER','ADMIN'])`。
- 缓存：badge-counts 用 `Redis`，写入消息队列失效。
