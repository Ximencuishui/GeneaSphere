# 修谱工作流测试用例清单

> 前置说明：
> 被测系统：寻根路修谱后台修谱工作流（8 个主节点）
> 两种模式：`serial` 严格串行（默认） / `free` 自由补录
> 状态：`todo` 待办 / `done` 完成 / `current` 当前 / `returned` 回流驳回 / `suspended` 搁置
> 权限：主修可推进、搁置、驳回；解锁定稿仅族长。普通族人只能提交勘误，不能直接改谱库
> 菜单 JSON、路由 path、其他侧边菜单保持当前版本。菜单高亮按 `route.fullPath` + tab

## 判定口径

8 个主节点，顺序固定：

| 序号 | key | 名称 | 记为 done 的条件 |
| --- | --- | --- | --- |
| 1 | project | 新建族谱项目 | 进入已有族谱后台即完成，恒为 done |
| 2 | digitize | 旧谱电子化 | 子步骤全部完成，或谱库已有人物，或已有保存记录 |
| 3 | internal_review | 谱稿初审 | 已有生平审核记录（通过或驳回都算） |
| 4 | errata_notice | 下发族人勘误 | 已有勘误通知或短信 |
| 5 | errata_revise | 汇总勘误、修订谱稿 | 已有审核过的勘误 |
| 6 | lock | 终审定稿 | `settings_json.xiupu.lock` 存在 |
| 7 | render | 册谱版式渲染 | 已有册谱卷宗 |
| 8 | print | 预览、印刷出谱 | 已有印刷订单 |

进度 = `status === done` 的节点数 / 8。`returned`、`suspended`、`current`、`todo` 都不计入。

严格串行：第一个不是 done 的节点之后，全部 `blocked`。置灰节点点击无效，圆点显示序号。自由补录：前置校验放开，`blocked` 全为 false。两种模式都不放开「未锁谱不能生成册谱」。

悬停看本节点之前第一个不是 done 的节点（blocker）：

- blocker 为 `returned`：`{returned_from_label}环节已驳回，请先处理：{blocker 名称}`
- blocker 为 `suspended`：`本项目当前已搁置，恢复流转后才可继续推进`
- blocker 为 `current` 或 `todo`：`请先完成上一环节：{blocker 名称}`

第一个未完成的 `todo` 会被标成 `current`。阻塞点本身通常是 `current`、`returned` 或 `suspended`。

回流落点：

- 谱稿初审驳回：`digitize` = returned，`returned_from_label` = 谱稿初审
- 勘误驳回：`errata_revise` = returned
- 终审驳回、族长解锁：`lock` 记录清空，`lock` = todo；`errata_revise` = returned，来源为终审定稿

驳回条标题为 `驳回：{原因}`，下方为处理要求。进度旁警告的原文是 `⚠️ 存在驳回回流项，请先修订。`，任一节点为 returned 就显示。

模式、搁置、重新送审写入 `PATCH /api/genealogy-workflow/settings`，绑定当前族谱的 `settings_json.xiupu`，不是全局开关。谱稿初审驳回、勘误驳回、终审驳回、解锁分别走各自业务接口。

## 前置准备

1. 项目 A：空族谱，严格串行。无人物、无审核、无勘误、无锁谱、无册谱卷宗、无印刷订单
2. 项目 B：同一数据条件下切换为自由补录。开关在「新建族谱项目」页
3. 账号：主修、族长、普通族人
4. 核对：进度、置灰、悬停、驳回条、警告标签、接口状态、面包屑、侧栏高亮、按钮是否可点

## 模块1：严格串行模式 serial（核心流程）

| 用例ID | 场景描述 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| S01 | 空族谱的初始状态 | 1. 主修进入项目 A，模式保持严格串行 | 1. `project` = done；`digitize` = current；其后节点 todo 且 blocked 2. 进度 1/8 3. 谱稿初审及之后悬停：请先完成上一环节：旧谱电子化 |
| S02 | 串行按完成条件走完 | 1. 依次满足 8 个节点的 done 条件：项目已存在 → 旧谱电子化 → 谱稿初审通过 → 下发勘误 → 审核勘误 → 终审锁谱 → 生成册谱 → 产生印刷订单 | 1. 每完成一个，该节点变为 done，下一个未完成节点变为 current 并可进入 2. 进度按 done 数 / 8 增加 3. 排在第一个未完成节点之后的节点，即使数据上已满足完成条件，仍然置灰，圆点是序号 4. `lock` = done 后，册谱页「生成预览」可点 |
| S03 | 串行中途点击未解锁节点 | 项目 A 只完成新建族谱项目时，点击工作流上的「谱稿初审」 | 1. 节点置灰，地址不变 2. 悬停：请先完成上一环节：旧谱电子化 |

## 模块2：回流驳回分支测试

| 用例ID | 场景描述 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| R01 | 谱稿初审驳回，回流旧谱电子化 | 1. 串行下旧谱电子化已完成，进入谱稿初审 2. 驳回，原因填：缺少权威文献出处 | 1. `digitize` = returned，浅黄，`returned_from_label` = 谱稿初审 2. `internal_review` 因已有审核记录在数据上可为 done，但被串行拦住，不是 returned 3. 旧谱电子化之后的节点全部置灰 4. 悬停：谱稿初审环节已驳回，请先处理：旧谱电子化 5. 旧谱电子化页顶部：标题「驳回：缺少权威文献出处」，说明「请按驳回意见修订世系和人物资料，改完再提交谱稿初审。」 6. 页面底部出现「提交重新谱稿初审」 7. 进度旁出现「⚠️ 存在驳回回流项，请先修订。」 |
| R02 | 修订后重新提交谱稿初审 | 在 R01 上点击「提交重新谱稿初审」 | 1. `PATCH /api/genealogy-workflow/settings`，body 含 `resubmit: "digitize"` 2. 本次驳回条消失；`digitize` = done；`internal_review` = current 3. 串行下，谱稿初审之后的节点继续置灰，直到再次审完 4. 没有其他 returned 节点时，进度旁警告消失；仍有勘误回流时警告保留 5. 出现比这次送审更晚的新驳回后，旧谱电子化再次变为 returned |
| R03 | 勘误驳回，汇总勘误回流 | 1. 前面节点已是 done，进入汇总勘误、修订谱稿 2. 存在尚未被后续通过覆盖的勘误驳回 | 1. `errata_revise` = returned 2. 终审定稿、册谱版式渲染、预览、印刷出谱置灰 3. 汇总勘误页顶部为「驳回：{原因}」，说明要求按退回意见修订；族人提交的是勘误申请，主修审核通过后才入库 |
| R04 | 终审驳回，回流汇总勘误 | 1. 已锁谱 2. 在终审定稿页点击「退回修订」并填写原因 | 1. `POST /api/genealogy/:slug/finalize/reject` 2. `lock` 记录清空，`lock` = todo，不是 returned 3. `errata_revise` = returned，`returned_from_label` = 终审定稿 4. 其后节点置灰；悬停：终审定稿环节已驳回，请先处理：汇总勘误、修订谱稿 5. 汇总勘误页展示该驳回原因，处理要求为修订后再次提交终审定稿 |

| --- | --- | --- | --- |
| P01 | 当前节点搁置 | 1. 串行下旧谱电子化为 current 2. 主修点击「搁置当前环节」 | 1. `PATCH` body 为 `{ suspend: "digitize" }` 2. 该节点 status = suspended，圆点右上灰斜角 3. 其后节点全部置灰，悬停：本项目当前已搁置，恢复流转后才可继续推进 4. 标题旁标签：进度已搁置：旧谱电子化 5. 进入旧谱电子化页，顶部常驻：本项目当前已搁置，恢复流转后才可继续推进 6. 搁置节点本身仍可进入；suspended 不计入 done |

## 回归检查

- 模式、搁置、取消搁置、重新送审走 `PATCH /api/genealogy-workflow/settings`，字段为 `mode`、`suspend`、`resume`、`resubmit`
- 谱稿初审驳回来自生平审核；勘误驳回来自勘误审核；终审驳回走 `POST /api/genealogy/:slug/finalize/reject`；解锁走 `POST /api/genealogy/:slug/finalize/unlock`
- returned、suspended 不计入 done
- `mode`、`suspended`、`lock`、`final_reject`、`digitize_resubmitted_at` 写在当前族谱的 `settings_json.xiupu`
- 锁谱后不能改世系和人物核心信息，也不能把勘误审核通过后写入谱库；解锁后恢复
- 未锁谱不能生成册谱
- 普通族人只能提交勘误申请
- 家族管理里的「内部初审」菜单名称保持不变
