## 2. Round 10 — 数据库断连与恢复演练（6/6 PASS）

测试脚本：`tests/observability/round10-db-disconnect-drill.js`
日志：[round10-db-disconnect-2026-08-01T19-19-17-199Z.log](../observability/results/round10-db-disconnect-2026-08-01T19-19-17-199Z.log)

| 步骤 | 验证项 | 期望 | 实际 | 结果 |
|------|--------|------|------|------|
| 1 | 真实服务 3120 `/api/health` | 200 | 200 | ✅ |
| 1 | 真实服务 3120 `/api/health/ready` | status=ready + db.ok=true | `status=ready db.ok=true latency=88ms` | ✅ |
| 2 | 隔离实例 3122（不可达 DB） | 启动失败 + 非 0 退出 | 35.381s 后 exitCode=1（5×5s 重试后） | ✅ |
| 3 | 隔离实例 3123（真实 DB） | 17s 内 ready | 17.806s `status=ready db.ok=true latency=295ms` | ✅ |
| 4 | 真实服务 3120 经演练后仍 ready | status=ready | `status=ready db.ok=true latency=242ms` | ✅ |
| 5 | `/metrics` 稳定输出 | 200 + 关键指标 | 200 + 346 行（含 family_count/http_requests_total/prisma_query_duration） | ✅ |

**GO/NO-GO**: 6/6 PASS

**关键发现**：
- `PrismaService.onModuleInit` 在 DB 不可用时按 5×5s 重试后失败退出，进程不会被错误标记为 ready
- `queryWithRetry` 包裹运行时 DB 抖动（PRISMA_QUERY_MAX_RETRIES=2, 300ms 退避）
- 5xx 异常会自动触发 webhook 告警（Round 5 已验证）
- 隔离实例失败不影响主服务（3120 持续 ready）

**生成环境部署建议**：
```bash
pm2 start dist/main.js --name api \
  --max-memory-restart 512M \
  --log /var/log/geneasphere/api.log
# 探针：liveness=/api/health, readiness=/api/health/ready
# K8s/Helm 会自动隔离未 ready 的实例
```
